# The prototype's source

`index.html` one folder up is the BUILT page — one self-contained file with
everything written into it. This folder holds what it was built from, so the
prototype can be changed rather than replaced.

## What is here

```
main.tsx          starts the app
App.tsx           the page: top bars, the pinned sidebar, the search, and
                  which of the three views is showing
data.ts           every number in the prototype. Dummy, but deterministic —
                  the same metric always gets the same history
index.css         the colour and type variables, plus the base rules
components/
  DetailTable.tsx the grid, and the two openable column groups
  MetricView.tsx  one metric on its own, with the sub-industries it drives
  KimCard.tsx     a sub-industry card on the overview
  TrendDrawer.tsx the panel that opens from a sparkline
  TrendChart.tsx  the chart inside that panel
  Sparkline.tsx   the little line in the Trend column
  Loader.tsx      the pause between views
  icons.tsx       every icon, drawn as SVG — no icon library
```

## How to rebuild it after a change

Two steps, because the styling and the program are built by different tools.

**1. The program.** Bundle with esbuild. The flags matter:

```
esbuild _src/main.tsx --bundle --format=iife --jsx=automatic \
  --loader:.css=empty --minify \
  --define:process.env.NODE_ENV='"production"' --outfile=app.js
```

- `--format=iife`, never `esm`. A module script is blocked when the page is
  opened straight off the disk; a plain script is not.
- `--loader:.css=empty` skips `index.css`, because the stylesheet is built
  separately (see below).

**2. The stylesheet.** `app.css` was generated by Tailwind v4 from the classes
the app was using at the time, with the contents of `index.css` appended.
Utilities added by hand since then are in a marked block at the very end of
`app.css`. If you regenerate the whole stylesheet with Tailwind, that block
can go — everything in it is a plain Tailwind utility.

If you cannot run Tailwind, add any new utility class you use to that block by
hand. A class with no rule behind it fails silently, so check: search `app.css`
for each class name you introduce.

**3. Fold them into one file.** `index.html` is `app.css` inside a `<style>`
and `app.js` inside a `<script>`, plus a small handler that prints a failure
onto the page instead of showing a blank white box. One file means nothing to
fetch, nothing to rename and nothing to misplace.
